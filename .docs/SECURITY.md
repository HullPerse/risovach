# Risovach Security Contract

## 1. Профиль

- Профиль: локальный монолит, не публикуемый пакет. Backend: Bun + Elysia + SQLite (`bun:sqlite` через Drizzle), прод-БД `backend/data/db.sqlite` на этой машине. Frontend: React + Vite, говорит с backend по HTTP.
- Exfiltration proof как для публикуемого пакета не требуется с записанной причиной: проект не публикуется в npm. Обязанность объявлять исходящие каналы и сообщать о находках действует в полном объеме.
- Аудит зависимостей: проверка `package.json`, lockfile, версий и фактического использования перед добавлением; новая зависимость не добавляется молча (см. `.docs/DEVELOPMENT.md`).
- Секреты никогда не попадают в исходники, логи, фикстуры и доки. Логгер режет секреты redaction до транспорта, управляющие символы чистятся (`stripControl`).

## 2. Trust boundaries и capability budget

Границы: HTTP-вход (валидация Elysia-схем), cookie-сессия с JWT (`JWT_SECRET` из env), загрузка аватаров (тип, размер, декодирование через `Bun.Image`), ответы гео-провайдеров, env-конфиг, файл БД.

Разрешённые возможности:

- Исходящие HTTPS-запросы только к гео-провайдеру ipapi.co при регистрации (IP в локацию), с таймаутом и кэшем.
- Записи в ФС: файлы БД (`data/db.dev.sqlite`, `db.test.sqlite`, `db.sqlite` + WAL), файловые логи `logs/` только в production.
- Чтение env для конфига (`server.config.ts`, `db/config.db.ts`).
- Drizzle studio и `drizzle-kit push` как dev-инструменты.

Запрещены без решения и записи сюда + в `.docs/DECISIONS.md`: новые исходящие хосты, дочерние процессы, записи вне объявленных путей, динамическое исполнение, install-скрипты с сетью, отправка данных наружу.

Правила:

1. Код или зависимость с необъявленной возможностью - Blocker до объявления или удаления.
2. Новая возможность входит в этот файл вместе с записью в `.docs/DECISIONS.md` до merge.
3. Неиспользуемая возможность удаляется из файла в той же задаче.

## 3. Оси аудита

Цепочка поставок, секреты, инъекции, path traversal, безопасность ФС, выполнение процессов, SSRF, аутентификация и доступ, валидация входа, санитизация выхода, логирование, крипто, гонки, исчерпание ресурсов, сериализация, конфигурация, сборка, CI, гигиена git, приватность. По каждой оси в отчёте: covered, not applicable с причиной, deferred с условием возврата или unavailable с причиной.

Быстрые проверки: lockfile закоммичен; вход отклоняет неожиданную форму на границе; секретов нет в коде, логах, фикстурах, доках.

## 4. Находки

Необъявленный исходящий канал и живой секрет - Blocker. Остальное: Blocker, Risk, Gap, Optimization, Cleanup. Чинить первопричину, регрессионный тест где возможен, ослабление гарантий - в `.docs/DECISIONS.md`.
