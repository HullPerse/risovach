# Risovach Design System

Источник истины по UI и UX. Полные контентные правила - в `.docs/DEVELOPMENT.md` (разделы UI/UX, anti-slop).

## 0. Выбор пресета

Проект использует пресет neo-brutalism, зафиксированный в `.docs/DEVELOPMENT.md`. Смена пресета требует явного решения пользователя и записи в `.docs/DECISIONS.md`.

## 1. Пресет: neo-brutalism

- radius 0, жёсткие границы 2px, хард-тени, моноширинный шрифт.
- Не вводить произвольные цвета, радиусы, тени и отступы, если проектное значение уже есть.
- Каждый контрол: пользовательская задача, ясное состояние, полезное состояние отказа.
- Видимые контекстные действия вместо скрытого глобального поиска.
- UI-копии короткие, прямые, действие-ориентированные, на русском. Ошибки говорят что произошло и что делать дальше.

## 2. QueryStateView

Общий компонент `queryState.component.tsx` для loading, error, empty и success нормализованного query:

- `inline` (default): `SmallLoader` и `InlineError`.
- `compact`: уменьшенный `SmallLoader` и `SmallError`, без вложенной retry-кнопки (для кнопок и бейджей).
- `window`: `WindowLoader` и `WindowError` с retry-кнопкой при переданном `onRetry`.
- Явные `loadingFallback`, `errorFallback`, `emptyFallback` имеют приоритет над fallback варианта.
- Ветки guard идут последовательно; render-prop вызывается только после проверки `state.data`. Словарь состояний с non-null assertion запрещён.

## 3. Состояния

Каждая асинхронная поверхность проектирует loading, empty, error, disabled, dirty, stale и recovery до объявления готовности. Серверные данные идут через TanStack Query (`isLoading`/`isError`, фон через `isFetching`); состояния берутся из query и не дублируются вручную.

## 4. Правила

- Не добавлять UI потому что есть у другого продукта.
- Не дублировать shared-компоненты; перед новым проверить `ui/`, `shared/`, `lib/`.
- Цвет не единственный сигнал состояния; интерактив доступен с клавиатуры, фокус видим.
- Каждое визуальное решение защищается пользой: понимание, иерархия, скорость задачи, доступность.
